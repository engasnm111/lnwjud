Date: 2026-08-25
Branch: `dev`
Scope: local pre-release acceptance for v4.11.0 before the user installs the candidate installer.

## Claim boundary

v4.11 keeps one saved OpenAI tunnel identity and continuously reconciles a native managed runtime back to the current Desktop MCP loopback endpoint. It retries transient failures indefinitely with capped backoff until the user disables/stops the tunnel.

This build **does not claim strict zero downtime**. The installed official `tunnel-client` exposes managed runtime supervision and health/readiness/control-plane-poll checks, but its CLI does not expose a documented/testable ready-before-retire overlap or A/B handoff primitive. `readyBeforeRetire` and `strictZeroDowntime` therefore remain false and the UI/Doctor reports that capability boundary instead of inferring it from reconnect behavior.

## Outcome-driven correction evidence

The observed 22–25 minute stop was self-induced by lnwjud rather than a local tunnel failure. The former `RunBudgetGuard` appended `ใกล้หมด budget — อัปเดต tracker + สั่งงานยาวเป็น background เดี๋ยวนี้` to every tool result after 22 minutes. Runtime logs at the observed boundaries showed successful MCP calls and no tunnel warning, deadline, reconnect, or shutdown event.

The corrected candidate:

- removes all elapsed-time state and result rewriting from `RunBudgetGuard`;
- advertises MCP initialize instructions to keep using lnwjud until the requested outcome is complete;
- explicitly forbids stopping, handing off, or asking for `continue` merely because time passed;
- keeps durable tasks as an execution primitive and continues checking them until terminal while the run remains active;
- makes `session_handoff` recovery-only instead of a scheduled end-of-run action.

Regression evidence:

- a tool result remains byte-for-byte unchanged after a simulated 30-day elapsed interval;
- HTTP MCP clients receive the outcome-driven instructions and no 22/25/60-minute cutoff;
- MCP server suite: 43 files / 335 tests PASS;
- corrected v4.11 acceptance suite: 6 files / 24 tests PASS;
- release verification script including Electron E2E 3/3, build, catalog check, packaging contract, release gate, NSIS build, and final diff check: PASS;
- packaged Desktop `app.asar` and bundled STDIO runtime both contain the outcome-driven instruction and neither contains the old Thai budget warning.

No tag or GitHub Release is part of this pre-user-acceptance candidate. The remaining real ChatGPT Web acceptance is intentionally manual: install this corrected candidate, keep the same conversation, run one real goal beyond the former 25-minute boundary, and confirm ChatGPT continues until acceptance without waiting for `ทำต่อ`. Refresh the connector once after installation only if ChatGPT still exposes cached pre-fix metadata; no repeated refresh should be needed during the run. Strict zero-downtime is still not claimed because the installed official tunnel client exposes no provable ready-before-retire overlap primitive.
