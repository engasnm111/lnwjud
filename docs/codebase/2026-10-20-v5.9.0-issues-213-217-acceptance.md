## Issue #216 — macOS escaped-session containment (release blocking)

The current process-group observer cannot prove terminal zero activity for `setsid`/double-fork descendants that escape the original PGID. Root PID disappearance, an empty `ps` group, and closed inherited stdio are not sufficient evidence to release a shared writer reservation or to reclaim it as stale. The [Apple DTS response](https://developer.apple.com/forums/thread/851230) confirms that macOS currently offers no supported kernel-owned all-descendant termination boundary surviving the loss of every userspace supervisor; its proposed descendant-scoped Endpoint Security multi-process monitoring design reduces attacks by children but does **not** independently establish that owner-loss guarantee.

Before acceptance, implement and independently review a native architecture meeting the explicit threat model, or an OS-enforced VM boundary; prove descendant escape, double-fork, concurrent spawn/teardown, custodian loss, stale-reservation recovery, and normal safe release on real macOS arm64. Keep existing uncertain reservations fail-closed, keep ordinary durable-shell capacity separate from managed-writer reservations, and never treat synthetic PGID fixtures as cross-session security proof.

## Native Writer Recovery Deadlock and test candidate replacement

Following user testing of the previous installer, ChatGPT Connector observed that while durable task history could be read across sessions, workspace writer lease acquisition failed during `workspace_writer_lease_acquire(recoverAbandoned=true)` with `Unverified native process descendants block repository import`, blocking `run_goal`, `shell`, and `process_start`.

### Root Cause Analysis
1. **Undispatched Managed Writer Reservations**: Four stale active markers were preserved in `background-tasks/.index/v1/active/` with `phase: 0` (Prepared). They were undispatched attempts where `holdExclusiveProbe` (mutationKind: `repository_import`) failed verification because `verifyNativeTermination` did not invoke `abortBeforeLaunch` when the native service attempt was never dispatched (`proof.reason === 'NATIVE_SERVICE_ATTEMPT_NOT_DISPATCHED'`).
2. **Post-Restart Native Process Lifecycle Proof**: Upon service restart, in-memory runtime dictionaries were lost and attempts were classified as `TerminationUnknown` (`SERVICE_RESTART_REQUIRES_RECONCILIATION`), with no persistent kernel handle to verify whether descendant processes were still running or had terminated.

### Solution & Remediation
1. **Undispatched Attempt Abort**: In `packages/capabilities/src/shared-managed-writer-admission.ts`, `verifyNativeTermination` now detects `proof.state === 'termination_unknown'` with reason `'NATIVE_SERVICE_ATTEMPT_NOT_DISPATCHED'` and calls `this.nativeAuthority.abortBeforeLaunch(...)`. This transitions the undispatched service attempt to `launch_not_started`, releases the service reservation, and deletes stale active markers safely.
2. **Deterministic Win32 Job Object Naming & Inspection**: In `native/windows-containment-helper/ContainedProcess.cs`:
   - Added `OpenJobObject` P/Invoke (`JobObjectQuery | JobObjectTerminate`).
   - Assigned deterministic Job Object names: `GetJobName(attemptId) => @"Local\lnwjud-job-" + cleanId`.
   - Implemented `QueryJob(jobName)` and `TerminateJobByName(jobName, timeoutMs)`.
3. **Native Service Restart Reconciliation**: In `native/windows-containment-helper/WindowsServiceProcessRuntime.cs`:
   - `Inspect(identity, callerSid)` and `Cancel(identity, callerSid)` inspect named Job Objects via `OpenJobObject` across service restarts.
   - If the Job Object does not exist (`ERROR_FILE_NOT_FOUND`) or has 0 active processes (`ActiveProcesses == 0`), termination is verified from the OS kernel, transitioning the attempt to `TerminalVerified` and releasing the reservation.
   - If active descendant processes remain (`ActiveProcesses > 0`), the attempt remains `TerminationUnknown` with reason `ACTIVE_PROCESSES_REMAIN`, strictly enforcing fail-closed protection.
4. **Preserved Fail-Closed Invariants**: Reservation markers are never blindly deleted. Live descendants block exclusive operations until terminated or drained.
