> **Historical planning snapshot (2026-10-08):** Baseline version, future-tense milestones, and unchecked boxes below describe the situation *before* v5.8.0 was released. Default to one worker on `dev`; delegation and worktrees require separate human authorization. This document is self-contained when those skills are unavailable.

**Goal:** ส่งมอบ v5.8.0 ครบ 6 เรื่อง: workflows พร้อมใช้, call observability, ผลงานและการเปลี่ยนแปลงราย Goal, งาน Excel/CSV, ทรัพยากรและ Context Economy, และ dependency automation ที่ใช้ PR เดียวพร้อม cleanup.

**Tech stack:** TypeScript, Electron/React, Node 24.x, pnpm 10.15.0, node:sqlite, MCP SDK 2.0.0, Zod, Vitest/Playwright, platform-native capability providers.

**สถานะ:** แผนพร้อมส่งต่อ; implementation ทุก phase ยังไม่เริ่ม. การสร้างเอกสารนี้ไม่ได้แก้ runtime, bump version, commit, push, publish หรือสร้าง schedule.

### Source facts ที่มีผลต่อการออกแบบ

1. `packages/mcp-server/src/upgrade-runtime.ts`: `recipe_run` คืนแผนและ `sideEffectsStarted: false` แม้รับ `dryRun: false`; ห้ามอ้างว่าเป็น executor ที่ทำงานจริงอยู่แล้ว.
2. `GoalContinuationService.runGoal(actor, request)` ใช้ `workspaceId` + `goalKey` และมี lease/intent/checkpoint อยู่แล้ว. Scheduled continuation เป็นอีก orchestration boundary; ห้ามสมมติว่าการสร้าง Goal ต้องเปิด schedule.
3. `AuditEvent` มี workspace/session/action/duration และ `metadata`; SQLite ใช้ `audit_events.duration_ms` / `metadata_json`. Projection ปัจจุบันบางส่วนมี limit 500 และยังไม่มี workflow goal association ครบทุก mutation.
4. `ActivitySinkEvent` มี callId, phase, duration, timestamp และ trace fields; legacy events อาจจับคู่หรือระบุ transport ไม่ครบ.
5. `RuntimeDiagnosticsHistoryRecorder` มี memory/event-loop/MCP samples อยู่แล้ว; default interval 60 วินาที, max 360 samples. อย่าสร้าง recorder แข่งกัน.
6. `CheckpointService.restore` รองรับ `expectedCurrentHashes` และคืน rollback checkpoint แต่เส้น IPC restore ปัจจุบันยังส่งเพียง workspace/checkpoint. ต้องเพิ่ม task-aware route โดยรักษา route เดิม.
7. `OfficeRuntimeService.execute` ให้ native local Office actions ผ่าน Windows provider; macOS/Linux คืน provider-unavailable ตามจริง. ห้ามเปลี่ยนข้อความให้ดูเหมือน native parity โดยไม่มี provider.
8. `ProjectDetector` ปัจจุบันรู้จัก Node/Python/Rust/Go/PHP/Java/.NET แล้ว; งานนี้ไม่สร้าง detector ซ้ำ.
9. Dependency workflow ปัจจุบันใช้ branch ลงท้าย run ID จึงไม่ deduplicate PR และไม่ cleanup หลัง merge. PR #175 เคยมี CI awaiting maintainer approval; missing checks ไม่เท่ากับผ่าน.

## 2. Global constraints และขอบเขต

- พัฒนาบน `dev` เท่านั้น; ไม่สร้าง feature/hotfix/codex branch หรือ worktree ใหม่เอง.
- ข้อยกเว้นเฉพาะ dependency bot: อนุญาต branch ชั่วคราวชื่อคงที่ `automation/runtime-dependencies` ได้หนึ่ง branch ระหว่างมี update PR; หลัง merge/cleanup กลับเหลือ dev/main. ข้อยกเว้นนี้ไม่อนุญาต agent สร้าง branch สำหรับ feature development.
- Harness คง Off by default; explicit project/workspace opt-out และ preset precedence ต้องเหมือนเดิม.
- UI, MCP, IPC, direct STDIO ใช้ authority และ validation เดิม. ห้ามทำทางลัด renderer → fs/SQL/shell.
- Full Bypass คง semantics เดิม; rolling Goal mutation fence ยังต้องตรวจ current `goalLease` ทุกครั้ง. ไม่สร้าง token จาก hash หรืออ้างว่า session เดิมคือ ownership.
- เริ่ม workflow ใหม่แบบ unscheduled. ไม่สร้าง Native ChatGPT task, cron สำหรับ Goal, Windows scheduled task หรือ timer executor โดยอัตโนมัติ. GitHub dependency schedule เดิมเป็นคนละระบบ.
- ใช้ audit/checkpoint/Goal DB เดิม. Schema ใหม่ต้อง additive, มี pre-migration backup และ readback/rollback compatibility tests.
- ไม่เก็บ file contents, credentials, raw lease tokens, environment dumps หรือ command secrets ใน telemetry/ordinary audit. ใช้ redactor และ metadata ที่ bounded.
- ทุกเลขต้องแยก measured / estimated / unavailable; ค่าไม่ทราบใช้ null/status ไม่แทนด้วย 0, READY หรือ SUCCESS.
- UI มี Thai/English, keyboard/focus/empty/loading/error/stale states และ navigation ตาม layout เดิม.
- ไม่ refactor monolith ทั้งชุดเพื่อทำฟีเจอร์นี้; composition roots เพิ่ม wiring แล้วแยก logic ใหม่เป็น module.
- Excel/CSV ไม่เขียนทับ source เป็นค่าเริ่มต้น; formula/text/leading-zero/locale ต้องรักษาความหมาย. Native Office operations, file operations และ visual preview ต้องระบุ provider/fidelity.
- ไม่อ้าง live Windows/macOS/Linux, Office COM, host scheduling หรือ release acceptance จาก unit mock อย่างเดียว.
- ไม่มี marketplace, arbitrary user scripts, cloud synchronization, LLM provider ใหม่, mail/Teams sending, macro execution หรือ automatic OS process cleanup ในขอบเขต v5.8.0.

## 3. Contract decisions สำหรับทุก phase

ชื่อด้านล่างเป็น **new contracts ที่ต้อง implement** ไม่ใช่ API ที่มีอยู่แล้ว. Domain types อยู่ `packages/domain/src/workflow.ts` / `observability.ts`; JSON DTO อยู่ `packages/ipc-contracts/src/workflow-contracts.ts` และ export จาก index.

```ts
type WorkflowTemplateId =
  | 'project-check' | 'code-review' | 'release-readiness'
  | 'connection-check' | 'data-audit' | 'template-report';
interface WorkflowTemplate {

  requiredCapabilities: readonly string[];
  readOnly: boolean;
  estimatedEffort: 'small' | 'medium' | 'large';

}

  templateRevision: number;
  inputs: Readonly<Record<string, string>>;

  objective: string;
  steps: readonly { id: string; title: string }[];

| New service/function | Exact responsibility / return |
|---|---|

| `WorkflowStartService.start(actor, request, authorization?)` | `Promise<Result<WorkflowStartResult>>`; adapter สร้าง/รับ Goal เดิมและรักษา lease/engineering binding |

| `TaskResultService.get(actor, workspaceId, goalId)` | `Promise<Result<TaskResultSummary>>`; authority จาก Goal + observed mutation/artifact evidence |

Query/page/result/request DTO ให้ประกาศใน Phase 1 จาก field lists ด้านล่าง; enum/nullable/limits เป็น contract ไม่ใช่ค่าที่ caller เดา. `GoalLeaseProof` ใช้ existing domain type และ engineeringTask fields ต้องตรง existing engineering goal binding schema ใน ToolRegistry.

### Required DTO fields และ limits

- Workflow descriptor: `id, revision, titleTh, titleEn, descriptionTh, descriptionEn, category, inputFields, outputKinds, requiredCapabilities, readOnly, estimatedEffort`; built-in revisions เริ่ม 1.
- Draft: ไม่เกิน 16 input fields, field value 1,024 chars, serialized inputs 16 KiB, objective 2,048 chars, steps ≤20, acceptance ≤20; stable digest รวม template revision + normalized inputs + workspace identity.
- Call query: `workspaceId, goalId?, toolName?, transport?, since?, until?, limit?, cursor?`; default 200/max 500 ต่อ page, cursor `(timestamp,id)`; default window 60 นาที/max 24 ชม. Aggregate max 10,000 observed calls พร้อม `coverage/truncated`; ไม่อ่านทั้ง DB เข้าหน่วยความจำ.
- Call page: `items, nextCursor, sampledAt, coverage, truncated, totals`; server/tunnel percentiles ใช้คนละ sample population และแสดง sample count.
- Task result: `workspaceId, goalId, goalRevision, status, observedChanges, artifacts, checks, blockers, lastCheckpointId, evidenceCoverage`; checks มี `pending/running/passed/failed/stale/unknown`; artifacts มี `path, kind, sha256?, sizeBytes?, verification`.
- Mutation item: `operationId, goalId, intentRevision, path, action, beforeSha256?, afterSha256?, checkpointId?, result, observedAt, source`; metadata ไม่มี contents. Unattributed legacy changes ไม่ถูกนับว่าเป็นผลงาน Goal.
- Diff limit: 256 KiB/2,000 lines ต่อ request; binary เป็น metadata/semantic preview, ไม่ทำ fake text diff.
- Office requests: workspace, input path(s), explicit sheet/range/keyColumns/empty policy, reference template/mapping/output path สำหรับ report; mapping เป็น declarative cell/range mapping ไม่รับ JS/shell.
- Office result: `provider, fidelity, supportedFeatures, unsupportedFeatures, findings, scannedRows, scannedCells, coverage, inputHashes, outputArtifact?`; findings default 200/max 1,000; values อาจเป็น confidential จึงใช้ explicit range/detail expansion.
- Resource row: `taskId?, provider, pid?, processIdentity?, ownerClientId?, goalId?, role, cancelWithGoal, ownership, workingSetBytes?, cpuPercent?, sampledAt, canCancel`; unknown/shared/supporting ต้องไม่ใช้ปุ่ม cancel Goal-owned.
- Resource polling: visible view ≥2 วินาที, hidden view หยุด polling; reuse recorder เดิม 60 วินาที; data เกิน 120 วินาทีแสดง stale. ยึด measurement scope ไม่หาร Desktop RAM รวมเพื่อเดาว่า workspace ใช้เท่าไร.
- Context fields ใช้ `rawContextBytes, contextSentBytes, previouslySeenBytesAvoided, ledgerHits` และ coverage จาก ledger เดิม; ไม่แปลง bytes เป็น exact token/cost โดยไม่มี provider usage จริง.

### MCP / IPC exposure

- เพิ่ม MCP tools 6 ตัว: `workflow_templates` (read), `workflow_prepare` (read), `workflow_start` (Goal bootstrap mutation), `call_history` (read), `task_result` (read), `resource_snapshot` (read). เพิ่ม schemas/mutation classification/runtime fixtures/catalog ให้ครบ.
- `workflow_start` คืน current Goal lease/engineering continuation ผ่าน authority เดิมสำหรับ MCP worker; lease token ไม่เข้า ordinary audit หรือ renderer.
- Desktop มี IPC `listWorkflowTemplates, prepareWorkflow, getCallHistory, getTaskResult, getResourceSnapshot, restoreTaskCheckpoint, cancelOwnedGoalTask`; typed maps + main validation + preload validation. **ไม่มี Desktop auto-executor/start schedule**.
- Desktop เตรียม draft แล้วให้คัดลอกคำสั่งเรียก `workflow_start` ไปยัง AI ที่ผู้ใช้เลือก. การ prepare/copy ไม่สร้าง active Goal ที่ไม่มีผู้ทำงาน.
- `restoreTaskCheckpoint` request: `workspaceId, goalId, goalRevision, checkpointId, expectedCurrentHashes, userConfirmed`; main ตรวจ Goal/checkpoint binding และ current mutation authorization/lease อีกครั้งก่อน restore. ไม่เชื่อ renderer boolean เพียงอย่างเดียว.
- `cancelOwnedGoalTask` request: `workspaceId, goalId, taskId, provider`; main อ่าน trusted owner/trackedTasks แล้วใช้ `GoalTaskCancellationService.cancelForGoal`. ไม่รับ PID หรือ ownerClientId จาก renderer เป็น authority.
- เพิ่ม Office actions `audit_data, compare_cells, create_report` ใน `office_excel`; route เข้า service/provider เดียวกัน. ไม่สร้าง Office tool family ซ้ำ.

export function nearestRank(values: readonly number[], percentile: number): number | null {
  const sorted = values.filter(v => Number.isFinite(v) && v >= 0).sort((a, b) => a - b);
  if (sorted.length === 0) return null;
  return sorted[Math.max(0, Math.ceil(percentile * sorted.length) - 1)] ?? null;
}
```

### Pure state-machine contract/test example

```ts
interface DependencyUpdateInput {
  changed: boolean;
  branchOwnership: 'absent' | 'managed' | 'foreign' | 'unknown';
  openPr: { number: number; managed: boolean; headSha: string } | null;
  legacyOpenPrCount: number;
}
type DependencyUpdateDecision =
  | { action: 'none' }
  | { action: 'create' }
  | { action: 'update'; prNumber: number; expectedHeadSha: string }
  | { action: 'blocked'; reason: string };

it('reuses an existing managed PR instead of creating another', () => {
  expect(planRuntimeDependencyUpdate({
    changed: true, branchOwnership: 'managed', legacyOpenPrCount: 0,
    openPr: { number: 175, managed: true, headSha: 'a'.repeat(40) },
  })).toEqual({ action: 'update', prNumber: 175, expectedHeadSha: 'a'.repeat(40) });
});
```

**Decision order:** conflicting/legacy/foreign ownership → blocked; unchanged pins → none; managed open PR → update; absent managed ref + no PR → create; orphan/ref without proof → blocked. Tests ต้อง cover ทุก branch ของ order นี้.

**Regression scenarios:** no-change; same update twice; upstream next version reuses PR; legacy duplicates; manual head change; forged marker/label; conflicting merges; missing/waiting/failed/success CI; cleanup open PR/changed SHA/unmerged/protected ref; duplicate cleanup; target/hash/provenance mismatch.

**Exit:** lifecycle runs through verified update → one managed PR → exact-head CI → authorized merge → conditional cleanup; ไม่เพิ่ม branch ตามแต่ละ run.

### ก่อนจบ turn หรือส่งต่อ worker

- [ ] Checkpoint currentPhase/nextAction/plan step state/blockers/trackedTasks ทันทีหลัง state/milestone เปลี่ยน; ถ้างานยาวไม่มี milestone ให้ refresh ภายใน 10 นาที ตาม AGENTS.
- [ ] resumeContext เก็บ changedFiles, exact command/exit/count/results, decisions, failedAttempts, pendingValidation, resumePrerequisites, stateFacts และ artifacts; summary เป็นเพียง headline.
- [ ] บันทึก HEAD/dirty state, Goal id/revision/intent/current lease generation, exact running task/run IDs/providers/roles/ownership. Never persist raw lease tokens/credentials.
- [ ] แยก blocking_job จาก supporting_service; ไม่หยุด shared process หรือรับช่วง live/unknown worker ด้วย PID/session inference.
- [ ] Worker ใหม่อ่าน durable Goal + latest resumeContext ก่อน git diff/ledger แล้ว re-evaluate ownership. ถ้าต้อง rolling recovery โหลด workspace scheduled-continuation skill ปัจจุบัน.
- [ ] Known fixable code/test/CI failure เป็นงานถัดไปใน turn เดียวเมื่อยังทำต่อได้; ไม่ส่งต่อแค่คำว่า CI failed โดยไม่อ่าน exact job log.
- [ ] ต้องบอกว่ามี local proof, hosted proof, live provider proof และ customer/install smoke ส่วนใดแล้ว/ส่วนใดยังไม่มี.
